# 녹화 및 OCR 계획

> 상태: 계획 단계 / 미구현

## 목표

유미지지 데스크톱 Agent가 Xbox Game Bar의 백그라운드 녹화 설정에 의존하지 않고 자체적으로 게임 화면을 캡처·인코딩·버퍼링한다. POTG 자동 클립과 일반 녹화를 같은 기반 파이프라인 위에서 제공하되, 캡처 범위와 Yummi 오버레이 포함 정책은 모드별로 독립적으로 설정할 수 있게 한다.

## 기본 녹화 정책

| 모드 | 기본 캡처 대상 | Yummi 오버레이 기본값 | 사용자 변경 |
| --- | --- | --- | --- |
| POTG / 자동 클립 | League of Legends 게임 창 | 제외 | 포함/제외 선택 가능 |
| 일반 녹화 | 현재 게임 모니터/출력 | 포함 | 포함/제외 선택 가능 |

- POTG는 OCR과 후처리 정확도를 위해 가능한 한 HUD가 없는 게임 원본 프레임을 사용한다.
- 일반 녹화는 사용자가 실제 플레이 중 본 화면에 가깝게 Yummi 오버레이를 포함하는 것을 기본값으로 한다.
- 캡처 소스와 오버레이 포함 여부를 별도 설정으로 관리해, 장기적으로 `게임 창 + 오버레이 포함`이나 `모니터 + 오버레이 제외` 같은 조합도 지원한다.

## 녹화 파이프라인

예상 구조:

```text
Capture source
  -> optional recording compositor
  -> hardware/video encoder
  -> compressed ring buffer
  -> clip writer
  -> MP4
```

- 자체 최근 플레이 기능은 Agent가 관리하는 ring buffer를 사용한다.
- raw RGBA 프레임을 장시간 메모리에 보관하지 않고, 가능하면 H.264/HEVC 등 인코딩된 패킷을 순환 버퍼에 유지한다.
- POTG 이벤트 발생 시 이벤트 이전 구간과 이후 구간을 합쳐 저장할 수 있게 한다.
- Game Bar `RecordLastAsync`/rolling recording은 핵심 의존성으로 사용하지 않는다. 필요하면 초기 실험 또는 fallback 용도로만 검토한다.
- 전체 화면/독점 전체 화면, Alt+Tab, 해상도·모니터 변경, 캡처 세션 손실 후 자동 복구를 고려한다.

## 오버레이 합성 계획

### 1단계

- POTG: League 창 자체 캡처로 Yummi Game Bar 오버레이를 자연스럽게 제외한다.
- 일반 녹화: 모니터/출력 캡처로 화면에 보이는 오버레이를 포함한다.

### 장기 확장

녹화용 compositor를 추가해 실제 Game Bar surface가 캡처되는지에 의존하지 않고 녹화 영상의 오버레이 정책을 직접 제어한다.

예상 설정:

```text
녹화에 포함할 Yummi 요소
- LCU 상태
- 파티
- 내전 스코어
- YouTube
- 기타 패널
```

패널별 포함/제외는 초기 버전 필수 기능은 아니며, 캡처/인코딩 기반이 안정화된 뒤 확장한다.

## OCR 계획

OCR은 Game Bar 위젯이 아니라 Yummi Agent의 캡처/후처리 파이프라인에서 수행한다.

- 가능하면 오버레이가 없는 League 원본 프레임을 OCR 입력으로 사용한다.
- 전체 화면 전체를 매 프레임 OCR하지 않는다.
- 필요한 화면 영역(ROI)만 crop하고 필요한 시점/낮은 샘플링 빈도로 처리한다.
- 녹화 중 이미 확보한 프레임을 활용해 MP4를 다시 디코딩하는 비용을 줄일 수 있게 설계한다.
- 필요 시 저장된 클립을 대상으로 사후 OCR을 다시 수행할 수 있게 한다.

### OCR 사용 목적

- POTG 후보 선별 보조
- 결과 화면/점수/문구 인식
- 클립 메타데이터 및 썸네일 생성 보조
- 게임 종료 후 분석 및 검증

### OCR 비목표 / 정책 경계

- 실시간 전술 판단이나 플레이 지시를 제공하지 않는다.
- 플레이어가 원래 알 수 없는 숨겨진 정보를 추론·표시하는 데 사용하지 않는다.
- League 프로세스 메모리를 읽지 않는다.
- DLL injection, 게임 내부 메모리 구조 접근, 비공식 게임 상태 추출을 녹화/OCR 파이프라인에 사용하지 않는다.
- 캡처된 화면 픽셀과 허용된 LCU/API/ROFL 데이터만 별도 목적에 맞게 사용한다.

## 구현 단계

1. League 창 캡처와 모니터 캡처 방식 비교 및 PoC
2. 하드웨어 인코더 연결과 안정적인 MP4 출력
3. 압축 ring buffer 및 이벤트 전/후 구간 저장
4. POTG 자동 클립 파이프라인 연결
5. 일반 녹화 UI와 저장 위치/화질/FPS/오디오 설정
6. ROI 기반 OCR 파이프라인 추가
7. 캡처 소스와 overlay policy 완전 분리
8. 필요 시 녹화용 compositor 및 패널별 오버레이 포함 설정 추가

## 구현 전 결정할 항목

- League 창 캡처: Windows Graphics Capture와 다른 Windows 캡처 경로 비교
- 모니터/독점 전체 화면 캡처: DXGI Desktop Duplication 등 후보 검증
- GPU별 하드웨어 인코딩 경로와 fallback
- 기본 POTG ring buffer 길이 및 이벤트 이후 보존 시간
- 기본 FPS/해상도/비트레이트
- 게임 오디오·시스템 오디오·마이크 캡처 범위
- 기본 저장 폴더와 용량/자동 정리 정책
- OCR 엔진 및 지원 언어, ROI 정의 방식
